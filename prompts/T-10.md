# Objective
## Redesign the Pomodoro Companion Interface

---

## Role

You are a UI/UX-focused frontend developer. Approach this objective with an emphasis on clear visual design, responsive sprite animation, and accurate representation of user-selected Pokémon companions.

---

## Description

Redesign the current Pomodoro page by removing the grass tileset and replacing the existing multi-directional Pokémon movement with a platformer-style companion area. Only Pokémon selected or owned by the user should appear, rather than displaying every available Pokémon. Restrict sprite animations to idle and walking states that support horizontal movement. Update the companion card beneath the Pomodoro timer to display the selected Pokémon’s profile information, consistent with the provided screenshot.

---

## Primary Objective

Implement a simplified, platformer-style Pomodoro companion experience featuring only user-owned or selected Pokémon moving dynamically along the horizontal axis.

---

## Secondary Objectives

- Remove the grass tileset background from the companion area.
- Limit each Pokémon spritesheet to the required idle and walking states.
- Update the companion card to present the selected Pokémon’s profile rather than an animated sprite.
- Preserve dynamic, randomized companion behavior, including periods of movement and inactivity.

---

## Success Criteria

- The grass tileset background is no longer displayed.
- Only Pokémon owned or selected by the user appear in the companion area.
- Sprite animations use only `idle-left`, `idle-right`, `walking-left`, and `walking-right`.
- Pokémon move exclusively along the horizontal axis.
- Pokémon randomly alternate between moving and stopping.
- A Pokémon reverses direction and flips its movement when it reaches either edge of the container.
- The companion card displays the selected Pokémon’s profile in a layout consistent with the provided screenshot.
- Multiple implementation subagents work simultaneously on separate files without creating editing conflicts.

---

## Constraints

- Do not use the existing grass background.
- Do not display Pokémon that are neither owned nor selected by the user.
- Do not use sprite states other than `idle-left`, `idle-right`, `walking-left`, and `walking-right`.
- Restrict movement to the X-axis.
- Assign implementation subagents to different files to prevent conflicts.

---

## Context & Dependencies

- The current Pomodoro page displays a complete grass tileset with multiple moving Pokémon sprites.
- The current spritesheet implementation uses all available animation states.
- User ownership and selection data must determine which Pokémon are rendered.
- The provided screenshot defines the intended visual direction for the Pomodoro area and companion profile card.

---

## Supporting Tasks

### Visual Simplification
- Remove the grass tileset from the Pomodoro companion container.
- Redesign the container to support a clean, platformer-style presentation.

### Pokémon Selection and Display
- Retrieve and display only Pokémon owned or selected by the current user.
- Prevent unowned and unselected Pokémon from appearing.

### Sprite Animation
- Restrict animation handling to `idle-left`, `idle-right`, `walking-left`, and `walking-right`.
- Randomly transition Pokémon between idle and walking behavior.
- Keep movement horizontal and select the appropriate animation based on direction.
- Reverse direction and horizontally flip movement when a Pokémon reaches a container edge.

### Companion Card
- Replace the Pokémon sprite shown in the lower companion card with the selected Pokémon’s profile.
- Align the card’s presentation with the profile-oriented design shown in the reference screenshot.

### Parallel Implementation
- Use multiple subagents simultaneously during implementation.
- Assign each subagent to different files so their changes do not conflict.

---

## Detailed Breakdown

### Platformer-Style Movement

Pokémon should move only from left to right or right to left within the companion container. Their behavior must remain dynamic and randomized, allowing them to stop, idle, resume walking, and change direction. When a Pokémon reaches either horizontal boundary, it must reverse direction and use the corresponding directional animation.

### Animation-State Restrictions

Use only the four required states: `idle-left`, `idle-right`, `walking-left`, and `walking-right`. The displayed state must remain synchronized with whether the Pokémon is stationary or moving and with its current horizontal direction.

### Companion Profile Presentation

The card beneath the Pomodoro timer should represent the currently selected Pokémon through its profile information instead of rendering the animated companion sprite. Its layout and content hierarchy should follow the supplied interface reference.
