# Objective
## Pomodoro Screen Redesign with Randomized Pokémon Companion Sprites

---

## Role

You are a front-end UI/UX developer working on the existing study workspace web application. Approach this objective with the mindset, vocabulary, and priorities of that role.

---

## Description

The goal is to redesign the Pomodoro screen of the existing study workspace so that it matches the layout and visual style shown in the provided screenshot, delivered as a fully interactive page. As part of the redesign, the Pomodoro card becomes a live canvas where animated Pokémon companions appear. Seven Pokémon sprite sheets are available, each containing complete sprite states for idle and walking in all four directions (down, up, left, right). Only the first evolution of each Pokémon is used, since no evolution concept has been decided; the focus is strictly on the sprites themselves. Within the Pomodoro card canvas, sprite states occur at random, and the card's background uses `public/assets/background/grass.png`, tiled so it fully covers the Pomodoro card container.

Both the planning and implementation phases must be executed using parallel sub-agents: sub-agents handle exploration during planning, and multiple sub-agents run simultaneously during implementation. Implementation sub-agents must each edit different files to prevent conflicts.

## Detailed Breakdown

### Sub-agent Execution Model
For this planning and implementation, parallel sub-agents must be used. During the planning phase, sub-agents perform exploration of the codebase, sprite assets, and existing Pomodoro implementation. During implementation, multiple sub-agents run simultaneously to build the redesign, and each sub-agent is restricted to editing different files so that concurrent edits never conflict.

### Sprite States
Each Pokémon's sprite sheet provides eight directional states: four idle states (idle-down, idle-up, idle-left, idle-right) and four walking states (walk-down, walk-up, walk-left, walk-right). All of these states are in scope for the animation.

### Randomized State Behavior
Sprite states "happen in random" throughout the whole Pomodoro card canvas: which sprite state plays, and when it changes, is decided randomly rather than scripted. This randomized activity is scoped exclusively to the Pomodoro card's canvas area — sprites do not appear or animate anywhere else on the page or in the application.

### Tiled Grass Background
The Pomodoro card container's background is set to `public/assets/background/grass.png` with tiling enabled, so the texture repeats seamlessly and covers the entire card container regardless of its size.
