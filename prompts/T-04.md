# Objective
## Study Tools Section UI/UX Enhancement with Parallel Sub-Agent Execution

---

## Role
You are a front-end UI/UX engineer and sub-agent orchestrator. Approach this objective with the mindset, vocabulary, and priorities of a developer responsible for interface refinement, component reuse, and coordinated multi-agent implementation workflows.

---

## Description
The Study tools section of the application requires a focused UI/UX refinement pass spanning four pages: /notes, /exams, /progress, and /calendar. The changes aim to make the interface more approachable for non-technical users by rendering markdown content as a formatted preview instead of raw syntax, and to make the interface more polished and streamlined through card styling adjustments, tag chips, title truncation, context menus, and the removal of unnecessary page indicators and form fields. Two pages will additionally adopt existing design templates: /progress will use the KPI cards from the academy dashboard template, and /calendar will use the calendar template while keeping its existing functionality intact. Both the planning and implementation phases must leverage parallel sub-agents: exploration sub-agents during planning, and multiple simultaneous implementation sub-agents — each editing different files — to prevent conflicts.

---

## Primary Objective
Enhance the UI/UX of the Study tools section by applying the specified design adjustments to the /notes, /exams, /progress, and /calendar pages, executing planning through exploration sub-agents and implementation through multiple simultaneous task agents with their own sub-agents, each editing different files.

---

## Secondary Objectives
- **Task 1 — /notes:** Refine the notes page by removing the card's custom border, rendering note content as a formatted preview instead of a raw markdown editor, displaying tags as token-style badges/chips, and removing the page indicator in favor of a clean page header applied system-wide.
- **Task 2 — /exams:** Refine the exams page by applying title truncation, replacing edit/delete icons with a 3-dot context menu, separating the date and time form fields, removing the location field, and removing the page indicator in favor of a clean page header applied system-wide.
- **Task 3 — /progress:** Replace the existing KPI cards with the KPI cards from the /template/dashboard/academy template.
- **Task 4 — /calendar:** Adopt the calendar from /template/dashboard/calendar while preserving all existing calendar functionality unchanged.

## Detailed Breakdown

### Markdown Preview for Note Content
Note content must be presented in preview mode rather than as a live markdown text editor. Any markdown syntax in the content — for example, **text** for bold — must render as the actual formatted output (bold text). The guiding rationale is that all users are not programmers, so raw syntax should never be exposed in the reading view.

### Tag Tokens
When adding tags on the /notes page, tags must no longer appear as plain text. Instead, each tag should be represented as a token, such as a small badge or chip, providing a clearer visual affordance for individual tags.

### Page Header Standardization
The page indicators currently shown (e.g., an icon followed by "Notes" or "Exams & preparation") must be removed. In their place, only the page header should be displayed: "Notes — Write and organize notes by subject" for /notes and "Exams — Track upcoming assessments and review topics" for /exams. This header pattern must be applied consistently across all pages of the system.

### Exam Card Actions and Title Display
Exam card titles must truncate when they are too long, using text truncation. The individually visible edit and delete icons must be replaced by a single 3-dot (kebab) icon that opens a context menu on the cards, consolidating those actions.

### Exam Form Field Adjustments
The add-exam form must separate the current combined date-and-time input into two distinct fields — one for date and one for time. The location field must be removed entirely, as it is not needed.

### Template-Based Component Replacement
The /progress page must adopt the KPI cards defined in /template/dashboard/academy. The /calendar page must adopt the calendar defined in /template/dashboard/calendar, with the explicit requirement that its functionality remains unchanged after the swap.
