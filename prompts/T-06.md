# Objective
## System-Wide Tab Standardization and UX Refinements for /Subjects and Dashboard

---

## Role
You are a frontend developer. Approach this objective with the mindset, vocabulary, and priorities of that role.

---

## Description
This objective comprises four user interface refinements across the application, executed with a mandated parallel sub-agent workflow. First, every instance where a segmented control is currently being used as a tab must be replaced with the actual tab component, because tabs and segmented controls serve different purposes: tabs change the section on a single page, while segmented controls are intended for content rather than sections — and the system should use tabs consistently across all of its pages. Second, the /subjects page must be simplified by removing the grid and list toggle so that the grid is the only view. Third, opening a specific subject on /subjects must no longer redirect to a separate page; instead, all subject content should be presented in a dialog modal with proper hierarchy and without clutter, and subject cards must be made clickable so that clicking a card opens this dialog. Fourth, the dashboard's right panel should include a calendar, sourced from the existing calendar template card located at template/dashboard/productivity. Both the planning and implementation phases must leverage sub-agents: exploration during planning is delegated to sub-agents, and implementation runs through multiple sub-agents operating simultaneously on different files to prevent conflicts.

Apply the four specified UI refinements — replace all segmented controls with the actual tab component system-wide, make /subjects a grid-only view with a modal-based subject detail experience, and add a calendar to the dashboard's right panel — using parallel sub-agents for exploration and implementation.

## Detailed Breakdown

### Segmented Control vs. Tabs
The two components are explicitly distinguished by their semantics: tabs change the section on a single page, whereas segmented controls are tabs for content rather than sections. Because the system's navigation needs are section-based, every page of the system should use tabs, and any segmented control currently acting as tabs must be replaced with the actual tab component.

### /Subjects Modal Behavior
Opening a specific subject must keep the user on /subjects: instead of redirecting to a next page, the subject opens in a dialog modal. The modal must contain all of the subject's content, organized with proper hierarchy so that it is not cluttered. The interaction entry point is the subject card itself — cards must be clickable, and clicking one opens the dialog.

### Dashboard Calendar
The calendar is placed in the dashboard's right panel and is taken from the existing template card at template/dashboard/productivity, meaning that template card is the source for the new calendar rather than a newly built component.

### Parallel Sub-Agent Execution Model
The planning and implementation phases are explicitly structured around sub-agents.

#### Planning Phase
- Use sub-agents for exploration. Exploration of the codebase during planning must be delegated to sub-agents rather than performed sequentially by a single agent.

#### Implementation Phase
- Use multiple sub-agents simultaneously. The four tasks (and any code changes derived from them) should be distributed across sub-agents running in parallel rather than executed one after another.
- Each implementation sub-agent must be assigned a different set of files to edit. File boundaries between sub-agents must not overlap, so that concurrent edits cannot conflict.
