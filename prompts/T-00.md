# Objective
## Implement PokeDen Development Roadmap Phases 1–6

---

## Role

You are a software development and implementation agent. Approach this objective with the mindset, vocabulary, and priorities required to plan, coordinate, and implement the PokeDen user interface and functional static experience.

---

## Description

Implement the PokeDen project according to the analysis and requirements documented in `ANALYSIS - POKEDEN`. Use the phases defined in `ANALYSIS - POKEDEN\07 - DEVELOPMENT ROADMAP.md` as the implementation roadmap and complete Phases 1 through 6 in a single coordinated effort. The primary focus is a functional UI/UX implementation, even where the current experience must rely on static data. Use parallel sub-agents throughout planning and implementation to explore the project, divide work by phase, and edit separate files without conflicts.

---

## Primary Objective

Plan and implement PokeDen Development Roadmap Phases 1 through 6 in one coordinated execution, delivering a functional static UI/UX that follows the project documentation and existing design system.

---

## Secondary Objectives

- Use exploration sub-agents during the planning phase to examine the documentation, roadmap, existing application structure, and design references.
- Use multiple implementation sub-agents simultaneously, assigning them to separate files to avoid editing conflicts.
- Apply agents and sub-agents across every phase from Phase 1, “The local foundation is ready,” through Phase 6, “The whole study day stays connected.”
- Preserve Phase 7, “Student information becomes production-ready,” for future backend-focused development.

---

## Success Criteria

- All requirements documented for Phases 1 through 6 are implemented.
- The resulting UI/UX is functional, even where static data is used temporarily.
- Every roadmap phase from Phase 1 through Phase 6 is handled through coordinated agent and sub-agent work.
- Implementation sub-agents work on different files to prevent merge and editing conflicts.
- The interface uses only the available shadcn components.
- The visual design follows the existing implementation under `src\app\(template)`.

---

## Constraints

- Complete Phases 1 through 6 in a single coordinated implementation effort.
- Use parallel sub-agents for both planning exploration and implementation.
- Implementation sub-agents must edit different files to prevent conflicts.
- Use only the shadcn components available in the project.
- Follow the overall design established in `src\app\(template)`.
- The current implementation may use static data but must remain functionally interactive at the UI/UX level.

---

## Out of Scope

- Do not implement Phase 7, “Student information becomes production-ready.”
- Do not undertake the backend work associated with Phase 7 at this stage.

---

## Context & Dependencies

- Use `ANALYSIS - POKEDEN` as the authoritative source for the project’s overall context, information, and requirements.
- Use `ANALYSIS - POKEDEN\07 - DEVELOPMENT ROADMAP.md` to determine the scope and requirements of each development phase.
- Use the existing shadcn components provided within the project for all interface construction.
- Use `src\app\(template)` as the reference for the application’s overall visual design.

---

## Supporting Tasks

### Planning and Exploration
- [Tag: Parallel] Assign exploration sub-agents to review the PokeDen analysis, development roadmap, existing application structure, available shadcn components, and template design.
- Consolidate the exploration findings into an implementation plan covering Phases 1 through 6.
- Divide implementation work so that concurrently operating sub-agents modify separate files.

### Phased Implementation
- Implement Phase 1, “The local foundation is ready.”
- Implement all requirements associated with Phases 2 through 5 as defined in the development roadmap.
- Implement Phase 6, “The whole study day stays connected.”
- Use agents and sub-agents for every phase and run independent implementation work in parallel where possible.

### UI/UX Alignment
- Build the interface exclusively with the project’s available shadcn components.
- Match the overall design direction demonstrated in `src\app\(template)`.
- Ensure the static implementation remains functional and provides the intended UI/UX behavior.

---

## Detailed Breakdown

### Parallel Planning

Use multiple exploration sub-agents to inspect the relevant documentation and project files before implementation begins. Their findings must inform a unified plan that maps roadmap requirements to specific implementation tasks and files.

### Conflict-Free Parallel Implementation

Execute implementation work with multiple sub-agents operating simultaneously. Assign each implementation sub-agent distinct files so concurrent edits do not overlap or create conflicts.

### Roadmap Scope

Implement every roadmap phase from Phase 1 through Phase 6 during the same coordinated effort. Follow the requirements and sequencing documented in `ANALYSIS - POKEDEN\07 - DEVELOPMENT ROADMAP.md`.

### Static but Functional Experience

Prioritize the actual UI/UX and ensure it behaves functionally, even when backend integration is unavailable and static data must be used. Defer production-ready student information and its backend requirements until Phase 7 is ready for development.
