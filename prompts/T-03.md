# Objective
## Enhance the Overview Section UI Using Existing Template Components

---

## Role

You are a UI developer responsible for planning and implementing interface enhancements by adapting existing components and functionality from the application’s template pages.

---

## Description

Revise and enhance the Overview section by replacing existing interface elements with specified components from the `/template` pages. Reuse the Academy Dashboard KPI cards, File Manager “All files” cards, Kanban cards and functionality, and Productivity project cards in their corresponding application pages. Preserve the relevant content patterns and functionality of the selected template components. Plan and implement the changes using sub-agents, with parallel implementation agents assigned to different files to avoid editing conflicts.

---

## Primary Objective

Update the Dashboard, Subject, Tasks, and Study Planner pages with the specified UI components and functionality from their corresponding template pages.

---

## Secondary Objectives

- Replace the Dashboard page KPI cards with KPI cards from the Academy Dashboard template.
- Replace Subject page cards with the “All files” card design from the File Manager template.
- Integrate the Kanban cards, functionality, and task-category tabs from the Kanban template into the Tasks page.
- Replace Study Planner cards with project-style cards from the Productivity template.
- Use sub-agents for planning exploration and parallelize implementation work across separate files.

---

## Success Criteria

- The Dashboard page uses KPI cards sourced from the Academy Dashboard on `/template`.
- The Subject page uses the “All files” card design from `/template/dashboard/file-manager`, rather than the folder cards.
- The Tasks page uses the cards, Kanban functionality, and task tabs from `/template/dashboard/kanban`.
- The Study Planner uses project-section cards, such as the “Q2 Roadmap” card, from `/template/dashboard/productivity`.
- Parallel implementation agents edit different files to prevent conflicts.

---

## Constraints

- Reuse the specified components from the existing template pages.
- Do not use the File Manager folder cards for the Subject page; use the content-based “All files” cards.
- Use multiple sub-agents simultaneously during implementation.
- Assign implementation agents to different files to avoid conflicting edits.
- Each agent must work across all specified tasks and must also use its own sub-agents.
- Limit multi-agent execution to implementation to reduce token consumption, while still using sub-agents for planning-phase exploration as specified.

---

## Context & Dependencies

- The Academy Dashboard is available from the `/template` page.
- The File Manager design is available at `/template/dashboard/file-manager`.
- The Kanban design and functionality are available at `/template/dashboard/kanban`.
- The Productivity project-card design is available at `/template/dashboard/productivity`.
- The affected application areas are the Dashboard, Subject, Tasks, and Study Planner pages.

---

## Supporting Tasks

### Dashboard KPI Cards
- Locate the Academy Dashboard within `/template`.
- Replace the existing Dashboard KPI cards with the Academy Dashboard KPI-card components.

### Subject Cards
- Locate the “All files” cards at `/template/dashboard/file-manager`.
- Apply these content-based cards to the Subject page.
- Use the card pattern represented by content such as “Product roadmap 2027.pdf” and “Modified 5 minutes ago by Arham Khan.”
- Exclude the File Manager folder-card design.

### Tasks Kanban
- Locate `/template/dashboard/kanban`.
- Reuse its Kanban cards and associated functionality on the Tasks page.
- Incorporate the available task tabs, including All Tasks, Due, Upcoming, and other existing categories, into the Kanban experience.

### Study Planner Cards
- Locate the project-section cards at `/template/dashboard/productivity`.
- Apply the project-card design represented by the “Q2 Roadmap” card to the Study Planner.

### Agent-Orchestrated Planning and Implementation
- Use sub-agents to explore the relevant templates and affected pages during planning.
- Use multiple sub-agents simultaneously during implementation.
- Allocate different files to implementation agents to prevent edit conflicts.
- Ensure each agent addresses all specified tasks and delegates work to its own sub-agents.
- Restrict broader multi-agent execution to the implementation phase to control token usage.
